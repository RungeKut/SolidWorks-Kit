# SolidWorks-Kit

Инструмент для моделирования в SolidWorks скриптами: библиотека, база
проверенного знания и правила её ведения. Подключается к Claude Code как
скилл `/solidworks`.

```
SolidWorks-Kit/
├── skill/SKILL.md        точка входа для ИИ (подключён как скилл)
├── swkit/                библиотека Python
├── knowledge/            база знаний
│   ├── 00_ПРАВИЛА.md     правила ведения базы
│   ├── INDEX.md          карта базы и поиск по симптому
│   ├── 10_API/  20_ПРИЁМЫ/  30_ГРАБЛИ/  40_СРЕДА/
├── templates/new_project/ скелет нового проекта
├── tests/                сквозные проверки на реальном SolidWorks
├── tools/setup.ps1       установка на машине
├── tools/check_docs.py   проверка целостности базы
└── CHANGELOG.md
```

---

## Установка на новой машине

```powershell
git clone https://github.com/RungeKut/SolidWorks-Kit.git
cd SolidWorks-Kit
powershell -ExecutionPolicy Bypass -File tools\setup.ps1
```

Либо двойной щелчок по `Install-skill.bat` в корне набора — та же
установка, без набора команды руками.

Скрипт создаёт junction `~\.claude\skills\solidworks` -> `<репозиторий>\skill`,
прописывает `SWKIT_HOME`, проверяет Python (нужен **64-bit**) и ставит
`pywin32`. Прав администратора не требует.

Клонировать можно куда угодно — пути в наборе не зашиты: скрипты находят
корень через `SWKIT_HOME` или через junction.

После установки — **перезапустить Claude Code**, чтобы он увидел скилл:
скиллы перечисляются при старте.

## Работа с нескольких машин

Набор общий, поэтому порядок жёсткий.

**В начале работы — подтянуть:**

```bash
cd %SWKIT_HOME% && git pull --rebase
```

Работа со старой копией приводит к конфликтам и к потере уже найденного
знания. Если pull сообщил о конфликте — разобрать сразу, до моделирования.

**После каждой правки набора — отправить:**

```bash
git diff                                                # прочитать глазами
python tools/check_docs.py --project "<папка проекта>"  # стоп-слова
git add -A && git commit -m "кратко что и почему" && git push
```

Не в конце сессии, а сразу: новая запись в `knowledge/`, правка `swkit/`,
изменение `SKILL.md` — коммит и push. Знание, оставшееся на одной машине,
для остальных не существует.

Если push отклонён (кто-то успел раньше) — `git pull --rebase`, затем push
снова.

**В набор не попадает ничего о проектируемом изделии** — ни в файлы, ни в
текст коммита. Репозиторий публичный; название изделия, имена его деталей,
габариты и узнаваемые узлы убираются, примеры пишутся на отвлечённых телах.
`tools/check_docs.py` сверяет весь набор со стоп-листом
`tools/stoplist.txt` регистронезависимо, а с ключом `--project` — ещё и с
именем папки проекта и именами лежащих в ней моделей. Текст коммита
проверяет хук `commit-msg` (`tools/hooks`, включается через `core.hooksPath`
в `setup.ps1`) — коммит с названием изделия в сообщении не пройдёт.
Описание узла, по которому изделие узнаётся и без названия, не ловит ни то
ни другое, поэтому `git diff` всё равно читают глазами. Подробности —
`knowledge/40_СРЕДА/40-02`.

**Что в репозиторий не попадает** (см. `.gitignore`): модели `.SLDPRT` и
`.SLDASM`, экспорт, снимки, `__pycache__`, вывод тестов. Репозиторий — это
инструмент, а не архив проектов. Сами проекты живут отдельными папками и
при необходимости получают свои репозитории.

## Как обратиться к набору

### Гарантированно

```
/solidworks
```

Скилл вызывается явно — срабатывает всегда, ничего угадывать не нужно.
Можно сразу с задачей: `/solidworks построй плиту 2000×1000×200`.

### Обычно

Достаточно, чтобы в запросе было **что строим** и **где**. Любого из этих
слов хватает, чтобы набор подключился сам: SolidWorks, СолидВоркс, солид,
`.SLDPRT`, `.SLDASM`, STEP, смоделировать, построить деталь / сборку / узел /
корпус / кронштейн / раму / планировку, 3D-модель, CAD-модель, габариты,
масса, сопряжения, разрез, экспорт модели.

Ошибки COM тоже подхватывают набор: «Член группы не найден», «Несовпадение
типов», «Неизвестное имя», «FeatureCut4 вернул None».

### Пример хорошего запроса

Триггером тут служит первое слово; всё остальное — то, без чего работа
пойдёт по догадкам.

```
Смоделируй в SolidWorks кронштейн крепления редуктора.
Папка проекта: D:\Работа\Кронштейн

Размеры:
  плита основания      180 × 120 × 12 мм
  вертикальная стенка  120 × 90 × 10 мм, по короткой стороне основания
  два ребра жёсткости  60 × 80 × 8 мм
Отверстия:
  4 × ⌀11 в основании по углам, отступ 20 мм от краёв
  2 × ⌀25 в стенке, на высоте 55 мм от основания, межцентровое 70 мм
Материал: Простая углеродистая сталь.

Система координат: начало в углу основания, плита в плоскости «Сверху»,
Y — вверх.

Нужно: детали + сборка с сопряжениями, проверка объёма и габаритов,
изометрия и вид сверху в PNG, экспорт STEP.
```

### Что стоит указать в запросе

| Пункт | Зачем |
|---|---|
| Папка проекта | иначе файлы лягут не туда, куда вы ждёте |
| Размеры с единицами | «120» без «мм» — источник ошибки в 1000 раз |
| Материал | без него масса модели не имеет смысла |
| Система координат | если не задать, будет выбрана своя, и переделка обойдётся дорого |
| Что считать готовым | детали или сборка, нужны ли виды, чертёж, STEP |

Чего указывать **не** нужно: какие функции API вызывать, в каком порядке
строить, как проверять результат — это уже в наборе.

### Обновить сам набор

```
Занеси в базу знаний: FeatureRevolve2 с осевой линией в эскизе
отрабатывает только если ось выбрана вторым щелчком с mark=4 — проверил,
без этого возвращает None.
```

Слова «занеси в базу знаний», «запиши в грабли», «добавь в swkit» ведут в
`knowledge/00_ПРАВИЛА.md` и дальше по правилам: шапка со статусом, строка в
`INDEX.md`, строка в `CHANGELOG.md`.

> Скиллы перечисляются при старте Claude Code. Если набор только что
> создан или переименован, `/solidworks` появится со следующего запуска.

## Быстрый старт

SolidWorks должен быть запущен.

```python
import os, sys
sys.path.insert(0, os.environ["SWKIT_HOME"])   # ставит tools/setup.ps1
import swkit as sw

sw.utf8_console()
app = sw.app()
doc = sw.new_part(app)

with sw.Sketch(doc, sw.TOP) as sk:
    sk.rect(0, 0, 2000, 1000)          # миллиметры
sw.extrude(doc, sk.feature, 200)

sw.check_part(doc, "Плита", expect_volume_mm3=2000*1000*200,
              expect_box_mm=[2000, 200, 1000])
sw.save_as(doc, r"C:\проект\Плита.SLDPRT")
```

Новый проект: скопировать `templates/new_project`, заменить данные в
`params.py`, запустить `build.py`.

## Почему скилл, а не MCP-сервер

Главное требование к набору — **возможность обновлять его прямо во время
проектирования**. Оно и решило выбор.

| | Скилл + библиотека | MCP-сервер |
|---|---|---|
| Обновление по ходу работы | правка файла действует сразу | **нужен перезапуск Claude Code** |
| Что попадает в контекст | `SKILL.md`, остальное по требованию | описания всех инструментов сразу |
| Отладка | обычный Python, запускается вручную | через протокол, воспроизвести труднее |
| Работа без Claude | скрипты запускаются сами | нужен клиент MCP |
| Сложные вызовы (27 аргументов) | прямо, как есть | через обобщённую обёртку |

Решающий довод — первая строка. MCP-серверы поднимаются при старте сессии;
изменение сервера требует перезапуска Claude Code, то есть обновлять набор
«на ходу» невозможно. Скилл и библиотека — обычные файлы: правка действует
со следующего чтения.

**MCP при этом не отменяется.** Разделение такое:

| Задача | Чем |
|---|---|
| Разовое действие, разведка в открытой модели | MCP `solidworks` |
| Найти сигнатуру, перечисление, пример кода | MCP `swapi-pilot` |
| Построение проекта, повторяемость, проверки | `swkit` |

Скилл подключён junction-ссылкой, поэтому правки в наборе действуют сразу:

```
%USERPROFILE%\.claude\skills\solidworks  ->  <репозиторий>\skill
```

## Что даёт библиотека

`swkit` — не обёртка ради обёртки. В ней собрано то, на что уходит время
при работе с API напрямую:

* подключение к **запущенному** SolidWorks, а не запуск нового;
* сторож модальных окон — без него первое предупреждение аддина вешает
  скрипт навсегда;
* плоскости по индексу, а не по имени — независимо от языка интерфейса;
* миллиметры и градусы на входе, метры и радианы — внутри;
* сигнатуры `FeatureExtrusion3` (23 аргумента) и `FeatureCut4` (27) с
  разобранными позициями;
* автоподбор направления выреза;
* три способа сборки с явным правилом выбора;
* проверка результата числом с независимым ожиданием;
* честное разделение «проверено» и «не проверено».

## Что проверено, а что нет

Проверено сквозным прогоном на SolidWorks 2025 SP04 20.09.2026: подключение,
эскизы, вытяжки (в том числе со смещением), вырезы, материалы, цвет,
сохранение, сборка сопряжениями, статусы компонентов, снимки видов, экспорт
STEP, весь шаблон проекта целиком.

**Не проверено:** условия окончания `UPTO_NEXT`, `UPTO_SURFACE`, `MIDPLANE`;
вращение `revolve`; скругления `fillet`; чертежи.

**Не работает:** детектор пересечений компонентов — недоступен на этой
установке, есть обходной путь через объём
(`knowledge/30_ГРАБЛИ/30-06`).

Записи в базе знаний помечены статусом; записи без поля `verified` силы не
имеют.

## Проверка после обновления SolidWorks

```
python tests\test_detal.py      деталь: эскиз, вытяжка, вырез, проверка, STEP
python tests\test_sborka.py     сборка: сопряжения, статусы, проверка
python tools\check_docs.py      целостность базы знаний
```

Оба теста строят модели в реальном SolidWorks и сверяют объём и габарит с
независимым расчётом. Файлы остаются в `tests/vyvod/` — посмотрите на них.

Если тест упал после обновления SolidWorks, это значит, что поведение API
изменилось: найдите соответствующую запись в базе, перепроверьте и обновите
её по правилам раздела 7 `knowledge/00_ПРАВИЛА.md`.

## Обслуживание базы

Правила добавления, обновления и удаления записей — `knowledge/00_ПРАВИЛА.md`.
Коротко: запись делается в момент, когда причина найдена, а не «потом»;
дубликат хуже пробела; устаревшее помечается, а не стирается; непроверенное
никогда не выдаётся за проверенное.
