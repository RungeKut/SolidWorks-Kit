# Работа с репозиторием

Набор живёт в `https://github.com/RungeKut/SolidWorks-Kit` и разворачивается
на нескольких машинах.

## Обязательный порядок

```bash
cd %SWKIT_HOME%
git pull --rebase                                  # В НАЧАЛЕ работы
# ... правки набора ...
git diff                                           # ОБЯЗАТЕЛЬНО: см. ниже
python tools/check_docs.py --project "<папка проекта>"
git add -A && git commit -m "что и почему" && git push    # СРАЗУ после правки
```

Отправлять после каждой смысловой правки, а не в конце сессии: новая запись
в `knowledge/`, изменение `swkit/`, правка `SKILL.md`. Знание, оставшееся на
одной машине, для остальных не существует.

Push отклонён — значит кто-то опередил: `git pull --rebase`, затем push
снова. **После слияния — прогнать проверку заново и перечитать слитое.**
Git сливает текст, а не смысл: две правки одного файла с разных машин
складываются без конфликта и дают раздел, спорящий сам с собой. Один такой
шов уже был — раздел правил начинался «раз в несколько сессий» и
заканчивался «перед коммитом обязателен».

## Подготовка коммита: изделие в набор не попадает

Репозиторий **публичный**, а набор — знание об инструменте, а не история его
сборки. Ни в файлах набора, ни в тексте коммита не должно остаться ничего, по
чему можно узнать, что сейчас проектируется.

**Убирается:**

* название изделия, его марка, модель, обозначение;
* имена деталей, сборок и чертежей проекта — как в дереве, так и в файлах;
* габариты, массы и прочие числа изделия, если они не нужны самому приёму;
* характерные узлы, по которым изделие узнаётся и без названия;
* пути к папке проекта.

**Остаётся** всё, ради чего запись и пишется: поведение API, сигнатуры, углы
и допуски приёма, отвлечённый пример на плите, кронштейне, фасонном корпусе.
Обезличивание не снижает достоверности: воспроизводимость даёт описание
операции, а не имя изделия.

Порядок перед каждым коммитом, ни один шаг не пропускается:

```bash
git diff                                            # 1. прочитать, что уходит
python tools/check_docs.py --project "путь_к_папке_проекта"   # 2. стоп-слова
git add -A && git commit -m "..."                   # 3. текст коммита — тоже
```

Шаг 2 обязателен. `check_docs.py` сверяет **весь** набор со списком
`tools/stoplist.txt` регистронезависимо, а с ключом `--project` добавляет к
стоп-словам имя папки проекта и имена лежащих там моделей — их не нужно
помнить и вписывать руками.

### Стоп-лист — только локальный

`tools/stoplist.txt` **в репозиторий не попадает**: он в `.gitignore`,
заводит его `setup.ps1`, и у каждой машины он свой. До 24.09.2026 файл лежал
в репозитории — и тем самым сам публиковал названия изделий, которые
должен был скрывать: любой, кто открывал репозиторий, читал их списком.

`check_docs.py` считает ошибкой оба случая:

* файла нет — проверять не по чему (свежая машина без `setup.ps1`);
* файл снова под git — `.gitignore` не мешает вернуть его через
  `git add -f` или слиянием старой ветки. Убрать:
  `git rm --cached tools/stoplist.txt`.

Названия, лежавшие в стоп-листе до этой даты, остались в **истории**
репозитория: удаление файла из текущей версии историю не переписывает.
Вычистить их можно только переписью истории и принудительным push — это
решение владельца репозитория, а не обычная правка набора.

Стоп-лист переносится на другую машину руками (или не переносится: там
свои изделия). Хранить его в облаке рядом с репозиторием — та же утечка.

Шаг 3 закрывает хук `commit-msg`: он прогоняет текст сообщения через тот же
стоп-лист и **отклоняет коммит**, если название нашлось. «Воспроизведено на
кузове такого-то» заменяется на «воспроизведено на фасонном корпусе» — смысл
сообщения от этого не меняется.

Хук лежит в `tools/hooks/commit-msg` и включается не копированием, а
`core.hooksPath`. В репозиторий он приезжает сам, но **включать его надо на
каждой машине** — поэтому `check_docs.py` отдельно проверяет, включён ли он,
и без него не даёт зелёного света:

```bash
git config core.hooksPath tools/hooks          # это делает setup.ps1
git config swkit.project "<папка проекта>"     # необязательно, но полезно
```

Вторая строка добавляет к стоп-словам имя папки проекта и имена лежащих там
моделей — те же приметы, что `check_docs.py --project` берёт для файлов.
Обойти хук можно `git commit --no-verify`; делать это без причины не стоит.

Новое изделие — строка в локальном `tools/stoplist.txt` **до** первого
коммита в набор, а не после утечки.

### Автор коммита — публичный и задан для клона

Публичный репозиторий — публичное имя. В каждом клоне набора автор
задаётся **локально**:

```bash
git config user.name  "<публичное имя>"
git config user.email "<публичный адрес>"
```

Без этого git подставляет глобальные настройки машины, а на рабочей машине
это рабочее имя и корпоративный адрес. Так в историю набора ушли три
коммита от 21.09.2026. Стоп-лист и хук этого не ловят: имя автора не входит
ни в файлы, ни в текст сообщения. Поэтому `check_docs.py` отдельно требует
локально заданного автора, а `setup.ps1` напоминает о нём. Уже ушедшие
коммиты исправляет только перепись истории — решение владельца
репозитория.

### Чем это подтверждено

Проверка на посторонние проекты была в наборе с самого начала — и не сработала
трижды подряд по трём разным причинам:

| Что было | Почему пропустила |
|---|---|
| Искала только в `knowledge/` | название ушло через `CHANGELOG.md` |
| Сравнивала с учётом регистра | в стоп-листе слово строчными, в тексте — с большой |
| Текст коммита не смотрела | в двух сообщениях коммитов осталось название |

Отсюда нынешний вид: весь набор, регистронезависимо, плюс приметы из папки
проекта, плюс хук на текст коммита. Все три дыры закрыты механически, но
`git diff` глазами всё равно остаётся: стоп-лист ловит название, а не
описание узла, по которому изделие узнаётся и без названия.

Четвёртая дыра была не в проверке, а в самом стоп-листе: он лежал в
публичном репозитории и публиковал все названия разом. Закрыта 24.09.2026 —
файл локальный (раздел «Стоп-лист — только локальный» выше).


## ГЛАВНОЕ: gh auth login нельзя запустить из агентской оболочки

**Симптом.** Команда запускается и висит вечно, не выдавая ни строки вывода:

```
gh auth login --hostname github.com --git-protocol https --web
```

Файл вывода пустой, процесс жив, таймаут срабатывает, задача уходит в фон.
Со стороны неотличимо от медленной сети.

**Почему.** `gh auth login` — интерактивная команда. Она печатает одноразовый
код и ждёт **нажатия Enter**, чтобы открыть браузер. У инструментов агента
stdin подключён к пустому устройству: нажать Enter некому, и gh ждёт вечно.

Подача перевода строки через конвейер не помогает:

```bash
printf '\n' | gh auth login --web      # НЕ РАБОТАЕТ, тоже зависает
```

gh проверяет наличие терминала, а не просто читает stdin.

**Как правильно.** Авторизацию выполняет человек в своём терминале, один раз
на машину:

```
gh auth login --hostname github.com --git-protocol https --web
```

Флаги `--hostname` и `--git-protocol` заданы заранее, чтобы не отвечать на
лишние вопросы: останется нажать Enter, скопировать код и подтвердить в
браузере.

После этого всё остальное делается без участия человека:

```bash
gh repo create SolidWorks-Kit --public --source=. --remote=origin --push
git push
```

**Как проверить, нужна ли авторизация**, не подвешивая оболочку:

```bash
gh auth status        # мгновенно отвечает, интерактива не требует
```

Если ответ `You are not logged into any GitHub hosts` — останавливаться и
просить человека выполнить вход. **Не пытаться обойти**: любой вариант
запуска `gh auth login` из агентской оболочки закончится зависанием.

**Оставшиеся процессы.** Зависший `gh` продолжает держать консоль после
таймаута. Снимать так:

```bash
taskkill //F //IM gh.exe
```

## Свежеустановленный gh не виден в открытых оболочках

`winget install --id GitHub.cli --scope user` дописывает PATH, но **уже
запущенные** оболочки его не перечитывают. Полный путь на этой машине:

```
%LOCALAPPDATA%\Microsoft\WinGet\Packages\GitHub.cli_Microsoft.Winget.Source_8wekyb3d8bbwe\bin\gh.exe
```

Надёжнее найти его программно, чем полагаться на PATH:

```bash
find "$LOCALAPPDATA" -name gh.exe -path "*GitHub*" | head -1
```

## Что не попадает в репозиторий

`.gitignore` отсекает модели (`*.SLDPRT`, `*.SLDASM`), экспорт, снимки,
`__pycache__`, вывод тестов, метки блокировки `~$*` и стоп-лист
`tools/stoplist.txt`. Репозиторий — это инструмент, а не архив проектов;
сами проекты живут отдельными папками.

`.gitattributes` держит в репозитории LF, а у `*.ps1` — CRLF. Без этого
машины перезаписывали бы друг другу переводы строк во всех файлах, и каждый
коммит выглядел бы как полная переделка.

## Установка на новой машине

```powershell
git clone https://github.com/RungeKut/SolidWorks-Kit.git
cd SolidWorks-Kit
powershell -ExecutionPolicy Bypass -File tools\setup.ps1
```

Затем **перезапустить Claude Code**: скиллы перечисляются при старте, иначе
`/solidworks` не появится.
