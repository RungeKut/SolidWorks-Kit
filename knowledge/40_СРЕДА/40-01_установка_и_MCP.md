# Окружение

Набор живёт в git-репозитории и разворачивается на нескольких машинах.
Конкретные пути на них различаются — **зашивать их в скрипты нельзя**.

## Где лежит сам набор

Определять программно, а не по памяти:

```python
os.environ["SWKIT_HOME"]                          # ставит tools/setup.ps1
os.path.dirname(os.path.realpath(
    os.path.expanduser("~/.claude/skills/solidworks")))   # через junction
```

Готовый резолвер с запасными путями — `templates/new_project/build.py`,
функция `kit_root()`.

Установка на новой машине: `powershell -ExecutionPolicy Bypass -File
tools\setup.ps1` после клонирования. Скрипт создаёт junction, прописывает
`SWKIT_HOME`, проверяет Python и ставит `pywin32`.

## Вторая машина: SolidWorks 2021

База знаний собрана на 2025, но работа идёт и на машине с более старой
версией. Различия в поведении API отсюда вероятны — разбор и порядок
действий в `00_ПРАВИЛА.md`, раздел 11.

| Компонент | Версия | Путь |
|---|---|---|
| SolidWorks | 2021 SP05.1 (`29.5.1.0001`, в списке установленного `29.151.0001`), русская локализация | `C:\Program Files\SOLIDWORKS Corp\SOLIDWORKS` |
| Python | 3.13, **64-bit** | `C:\Python313\python.exe` |
| Установка набора | `Install-skill.bat` в корне (обёртка над `tools\setup.ps1`) | junction `~\.claude\skills\solidworks` |

Что на этой машине отличается от эталонной, кроме версии:

* **Шаблонов ГОСТ нет.** `swkit.find_template()` берёт то, что нашлось:
  `C:\ProgramData\SolidWorks\SOLIDWORKS 2021	emplates\MBD\part 0001mm and smaller.prtdot`.
  Деталь строится, но оформление у неё не ГОСТовское — для чертежей шаблоны
  нужно поставить.
* **Плоскости в дереве названы по-английски** — `Front Plane`, `Top Plane`,
  `Right Plane`, хотя локализация русская. Ровно поэтому плоскости
  адресуются индексом (`sw.TOP`), а не именем: на эталонной машине те же
  плоскости зовутся «Спереди», «Сверху», «Справа». Код, написанный по
  индексу, работает на обеих.

Из установленного рядом: eDrawings 2021 SP05.1, Composer Player, Visualize,
SOLIDWORKS CAM — на работу `swkit` не влияют.

Python здесь стоит в `C:\Python313`, а не в профиле пользователя, как на
эталонной машине. Ещё одна причина не зашивать пути: `tools/setup.ps1`
находит интерпретатор сам, а скрипты проектов берут корень набора из
`SWKIT_HOME`.

Всё ставилось **без прав администратора**, в профиль пользователя.

Шаблоны и база материалов — машинные, в репозиторий не входят. На новой
машине их может не быть: `swkit.find_template()` тогда ищет любой шаблон на
диске, а `swkit.materials.write()` сообщит, что базы нет, и подскажет, как
её создать.

## Запуск SolidWorks, если он не запущен

`swkit` подключается к **уже запущенному** SolidWorks: холодный старт
занимает больше минуты, а подключиться можно только после того, как
приложение зарегистрируется в таблице запущенных объектов (ROT). Пока этого
не произошло, `GetActiveObject` бросает исключение, и `sw.app()` поднимет
**второй** экземпляр вместо ожидания.

Запуск:

```powershell
Start-Process "C:\Program Files\SOLIDWORKS Corp\SOLIDWORKS\SLDWORKS.exe"
```

Ожидание готовности — циклом, а не паузой наугад:

```python
import time
import pythoncom
import win32com.client
import win32com.client.dynamic

pythoncom.CoInitialize()
app, t0 = None, time.time()
while app is None and time.time() - t0 < 420:
    try:
        app = win32com.client.dynamic.Dispatch(
            win32com.client.GetActiveObject("SldWorks.Application"))
    except Exception:
        time.sleep(3)
if app is None:
    raise RuntimeError("SolidWorks не поднялся за 7 минут")
```

Дальше — обычное `sw.app()`: оно подключится к этому же экземпляру и заодно
поставит сторож модальных окон.

**Окно после такого старта невидимо**: сразу после регистрации в ROT
`app.Visible` равно `False`. `sw.app()` ставит `Visible = True` сам;
при прямой работе с COM выставляйте явно, иначе построение идёт вслепую и
снимки берутся с несуществующего окна.

Проверено 21.09.2026 на 2021 SP05.1: после такого запуска обе сквозные
проверки из `tests/` проходят целиком.

## Синхронизация

```bash
cd %SWKIT_HOME%
git pull --rebase                 # в начале работы
git add -A && git commit -m "..." && git push    # после каждой правки
```

Модели, экспорт и снимки в репозиторий не попадают (`.gitignore`): это
инструмент, а не архив проектов.

## Запуск скриптов

```python
import os, sys
sys.path.insert(0, os.environ["SWKIT_HOME"])
import swkit as sw
```

Постоянная установка библиотеки в Python не делается намеренно: набор
правится по ходу работы, и лишний шаг переустановки только мешал бы.

## Два MCP-сервера

| Сервер | Транспорт | Что даёт |
|---|---|---|
| `solidworks` | stdio, локальный | 132 инструмента управления SolidWorks |
| `swapi-pilot` | HTTP, внешний | поиск по официальной документации API |

**Важно про `--real`.** Сервер `solidworks` зарегистрирован с ключом
`--real`. Без него он стартует в **mock-режиме** и отвечает «готово» на все
команды, ничего не делая (`mock_mode = not args.real`).

**Про данные `swapi-pilot`.** Это внешний хостинговый сервис. Туда уходят
поисковые запросы по API — имена методов и интерфейсов. Геометрия и файлы
моделей не уходят. Если политика по данным строгая, у локального сервера
есть свой поиск: `search_solidworks_api_help`, `lookup_api_method`,
`lookup_api_interface`, `find_related_api_members`.

## Когда MCP, а когда swkit

| Задача | Чем |
|---|---|
| Разовое действие, разведка | MCP `solidworks` |
| Найти сигнатуру, перечисление, пример | `swapi-pilot`, `search_solidworks_api_help` |
| Построение проекта, повторяемость, проверки | **`swkit`** |

Причина разделения не в качестве сервера, а в характере задачи: реальному
моделированию нужны точные вызовы с двумя десятками позиционных аргументов
и проверка результата на каждом шаге, а обобщённые обёртки этого не дают.
MCP остаётся удобен для разведки и разовых операций.

## Требования, нарушение которых ломает всё

* **Python только 64-bit.** 32-битный физически не получит COM-объект
  64-битного SolidWorks. Проверка:
  `python -c "import platform; print(platform.architecture()[0])"`.
* **SolidWorks в интерактивной сессии**, не служба и не заблокированный RDP:
  без рабочего стола ломаются виды и снимки.
* **Единицы API — метры и радианы.**

## Восстановление окружения с нуля

Всё ставится в профиль пользователя, права администратора не нужны.

```powershell
# 1. Python 3.13 64-bit
winget install --id Python.Python.3.13 --scope user --silent `
    --accept-package-agreements --accept-source-agreements

# 2. Проверка разрядности — ОБЯЗАТЕЛЬНО, иначе дальше идти бессмысленно
$py = "$env:LOCALAPPDATA\Programs\Python\Python313\python.exe"
& $py -c "import platform; print(platform.architecture()[0])"   # ждём 64bit

# 3. Мост к COM
& $py -m pip install pywin32

# 4. Проверка связи с SolidWorks (SolidWorks должен быть запущен)
& $py -c "import win32com.client as w; a=w.GetActiveObject('SldWorks.Application'); print('OK', a.Visible)"
```

Для самого набора этого достаточно: `swkit` подключается через `sys.path` и
не требует установки.

MCP-серверы ставятся отдельно и для работы `swkit` **не нужны**:

```powershell
claude mcp add solidworks --scope user -- `
    "C:\dev\SolidworksMCP-python\.venv\Scripts\python.exe" `
    "C:\dev\SolidworksMCP-python\src\utils\start_local_server_claude.py" `
    --real --year 2025
claude mcp add swapi-pilot --scope user --transport http https://swapi-pilot.com/mcp
```

Ключ `--real` обязателен, иначе сервер работает в mock-режиме. Ключ
`--year` называет версию SolidWorks: на машине с 2021 это `--year 2021`.
После изменения конфигурации MCP нужен перезапуск Claude Code.
