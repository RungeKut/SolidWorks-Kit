# Подключение к SolidWorks

## Три режима связывания и что выбрать

| Режим | Как | Плюс | Минус |
|---|---|---|---|
| Позднее | `win32com.client.dynamic.Dispatch` | проходят любые сигнатуры | члены не видны, нужны `prop`/`call` |
| Обычное | `win32com.client.Dispatch` | проще | непредсказуемо, зависит от кэша gencache |
| Раннее | `gencache.EnsureModule` + приведение | видны имена и типы | строгая проверка типов ломает `SaveAs(None)` |

**Выбор по умолчанию — позднее.** Это единственный режим, который
выдерживает все вызовы SolidWorks без исключений. Раннее применяется
точечно, когда нужен конкретный интерфейс из типовой библиотеки.

Режим связывания — главный источник расхождений в поведении одного и того
же кода. Вызов, годами работавший при раннем связывании, при переносе на
позднее падает на аргументах (см.
[30-05](../30_ГРАБЛИ/30-05_byref_и_адресация_выбора.md)).

## Подключение

```python
import swkit as sw

sw.utf8_console()            # кириллица в консоли
app = sw.app(verbose=True)   # ATTACH к запущенному, иначе DISPATCH
```

`sw.app()` делает:

1. `GetActiveObject("SldWorks.Application")` — подключиться к **уже
   запущенному** экземпляру;
2. если не вышло — `Dispatch`, поднять новый;
3. `Visible = True`;
4. поднять сторож модальных окон.

**Почему сначала attach.** Холодный старт SolidWorks занимает больше минуты,
упирается в диалоги лицензии, которые некому нажать, а при работе с уже
открытой сессией видно на экране то же, что делает скрипт.

Рекомендуемый порядок работы: запустить SolidWorks вручную, потом
запускать скрипты.

## Два хелпера, без которых не обойтись

```python
from swkit.conn import prop, call

prop(doc, "GetTitle")            # читать член: значение или объект
call(asm, "AddComponent5", ...)  # вызывать метод с аргументами
```

`prop` — когда член **возвращает** значение без аргументов.
`call` — когда члену нужны **аргументы** или его нет в дефолтном dispatch.

Почему нельзя обойтись одним `getattr`, разобрано в
[30-01](../30_ГРАБЛИ/30-01_callable_на_CDispatch.md) и
[30-04](../30_ГРАБЛИ/30-04_члены_интерфейсов_вне_dispatch.md).

## Раннее связывание точечно

```python
from win32com.client import gencache
from swkit.conn import cast, TYPELIB

S = gencache.EnsureModule(TYPELIB, 0, 33, 0)
asm = cast(S.IAssemblyDoc, doc)
asm.ToolsCheckInterference2(0, None, False)
```

GUID типовой библиотеки: `{83A33D31-27C5-11CE-BFD4-00400513BB57}`,
версия 33.0 соответствует SolidWorks 2025.

Раннее связывание полезно ещё и для **разведки**: в сгенерированном модуле
видны все интерфейсы и сигнатуры, по нему можно искать методы, когда
документация не помогает. Путь к сгенерированному коду:

```python
import win32com.client.gencache as g
print(g.GetGeneratePath())
```

## Требования к окружению

* **Python 64-bit обязательно.** SolidWorks 2025 — 64-битное приложение;
  32-битный Python физически не получит его COM-объект.
  Проверка: `platform.architecture()[0] == '64bit'`.
* Python 3.8 или новее (на этой машине стоит 3.13).
* `pywin32`.
* SolidWorks в обычной интерактивной сессии, не под заблокированным RDP.

Подробности установки — [40-01](../40_СРЕДА/40-01_установка_и_MCP.md).

## Закрытие документов

```python
sw.close_all(app)            # перед пересборкой — обязательно
sw.close(app, doc)           # конкретный документ
doc = sw.open_doc(app, path) # тип определяется по расширению
```
