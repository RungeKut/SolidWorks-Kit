# Сборки

## Три способа расстановки

Способов три, у каждого своя область.

| Способ | Функция | Когда применять |
|---|---|---|
| 1. По координатам | `by_coordinates` | быстрый визуальный макет, сопряжения не нужны |
| 2. Матрицей | `by_transform` | деталь смоделирована в своей ориентации и в сборке повёрнута |
| 3. Сопряжениями | `by_origin_mates` | **основной способ**, когда детали строятся скриптом |

**Правило выбора: если детали моделируются скриптом — всегда способ 3.**
Моделируйте каждую деталь сразу в координатах сборки; тогда совпадение
одноимённых базовых плоскостей ставит её точно на место, и компонент
получает статус «полностью определён».

Цена ошибки при выборе способа 1: компоненты остаются зафиксированными по
координатам. Модель выглядит правильно, но при любом перестроении или
изменении детали ничего не пересчитывается — связей нет.

## Порядок сборки способом 3

```python
import swkit as sw

app = sw.app()
sw.close_all(app)

asm = sw.new_assembly(app)
sw.save_as(asm, ASM_PATH)         # ОБЯЗАТЕЛЬНО до вставки, см. ниже
sw.preload(app, ASM_PATH, paths)  # открыть детали + активировать сборку
asm = app.ActiveDoc

for p in paths:
    comp, ok, bad = sw.by_origin_mates(app, asm, ASM_PATH, p)
    print(os.path.basename(p), "сопряжений", ok, "ошибок", bad)

sw.rebuild(asm)
sw.save_as(asm, ASM_PATH)
sw.check_assembly(asm, expect_components=len(paths))
```

### Почему сохранять сборку до вставки

Имя сборки входит в адрес выбора: `Спереди@Основание-1@Тест_сборка`. Пока
сборка не сохранена, она называется `Сборка18`, и адреса не совпадут.
При этом сохранять нужно **правильным флагом** — флаг 2 не переименовывает
документ, см. [30-03](../30_ГРАБЛИ/30-03_SaveAs_флаг_копии.md).

### Почему preload

`AddComponent5` берёт только тот документ, который SolidWorks **уже
загрузил**. Без предварительного `OpenDoc` он молча возвращает `None`.
После открытия деталей активным становится последняя открытая деталь —
поэтому `preload` в конце активирует сборку.

## Что делает by_origin_mates

1. `AddComponent5` в точку (0, 0, 0) — компонент вставляется
   **зафиксированным**;
2. выбор компонента по имени `Имя-1@Сборка` и `UnfixComponent` — снять
   фиксацию, иначе сопряжения не нужны и не создадутся осмысленно;
3. три совпадения: `Спереди@Имя-1@Сборка` ↔ `Спереди` и так для трёх
   плоскостей.

Возвращает `(компонент, число_сопряжений, число_ошибок)`. **Проверяйте
число ошибок** — неудачный выбор не бросает исключение.

## Статусы компонентов

`GetConstrainedStatus()` — главный признак здоровья сборки.

| Код | Значение | Проверено |
|---|---|---|
| 0 | неизвестно | нет |
| 1 | переопределён | нет |
| **2** | **недоопределён** | **да** |
| **3** | **полностью определён** | **да** |
| 4 | нет решения | нет |

Коды 2 и 3 путают постоянно, в разных справочниках они указаны по-разному.
Проверено экспериментом 20.09.2026:

```
компонент вставлен и зафиксирован          -> 3
фиксация снята, сопряжений нет (свободен)  -> 2
фиксация снята, 3 совпадения плоскостей    -> 3
```

То есть **3 = полностью определён**. Зафиксированный компонент тоже
считается полностью определённым.

```python
print(sw.status_report(asm))
# {'полностью определён': 3}
```

**Недоопределённые компоненты уедут при следующем перестроении.** Модель,
правильная сегодня, развалится завтра, и причину будет не найти. Поэтому
`check_assembly(require_fully_defined=True)` — обязательная проверка.

## Вставка по координатам (способ 1)

```python
sw.by_coordinates(app, asm, path, x=0, y=440, z=-1000)
```

Тонкость: `AddComponent5` ставит компонент **центром габаритного ящика**, а
не началом координат. Если деталь смоделирована не вокруг своего начала,
разницу надо добавить обратно — `compensate_bbox=True` делает это через
`bbox_centre_mm`.

## Вставка матрицей (способ 2)

```python
sw.by_transform(app, asm, path,
                rotation=sw.mul(sw.rz(180), sw.rx(90)),
                translation=(0, 0, 500))
```

Матрица SolidWorks — 16 чисел: 9 поворота **по столбцам**, 3 переноса в
метрах, масштаб 1.0 и три нуля. Готовые `rx`, `ry`, `rz`, `mul` — в
`swkit.assembly`.
