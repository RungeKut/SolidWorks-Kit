# Данные отдельно от построения

## Суть приёма

Скрипт построения не должен содержать чисел. Все размеры — в отдельном файле
данных; скрипт читает их и строит.

```
params/vehicle.json     ← единственный источник истины
   |
   +-- calc/*.py        расчёты читают отсюда
   +-- cad/build_*.py   построение читает отсюда
   +-- docs/*.md        документация генерируется из результатов расчёта
```

Изменение одного числа в файле параметров и запуск одного скрипта
пересобирают расчёты, CAD-модели, проверки и документацию. Числа в
документации берутся из результатов расчёта, поэтому **разойтись с расчётом
не могут**.

## Две формы источника истины

| Форма | Когда | Пример |
|---|---|---|
| JSON | данные нужны нескольким языкам или инструментам, есть расчёты | `params/изделие.json` |
| Модуль Python | данные нужны только Python, есть производные значения | `params.py` |

Модуль Python удобнее, когда часть данных вычисляется из другой части, и
когда нужны именованные константы:

```python
RC  = "Железобетон монолитный B25"
H0, H1 = 0, 2700          # низ/верх стен
SL     = 200              # толщина плиты

# (имя, материал, (x1,y1,x2,y2), z0, z1, [проёмы])
PARTS = [
 ("01_Плита_пола", RC, (160,285,9730,9340), -SL, 0, [(7670,7420,9730,9340,-SL,0)]),
 ("04_Стена_наружная_верхняя_ЖБ", RC, (160,9075,7670,9340), H0, H1, []),
]

DENS  = {RC: 2500, ...}   # для проверки назначения материала
COLOR = {RC: (0.61, 0.61, 0.62), ...}
```

Один список `PARTS` питает построение деталей, сборку, раскраску, проверку и
рисование плана. Тридцать деталей построены одной функцией.

## Именуйте точки, а не индексы

Плохо:

```python
profile = [(0, 420), (0, 1150), (420, 1200), (1800, 1400), (3050, 1796)]
apex = profile[4]           # сломается при первой же правке
```

Хорошо:

```python
P = {
  "bumper_bottom": (0,    420),   # низ переднего бампера
  "mask_top":      (0,   1150),   # верх маски
  "hood_front":    (420, 1200),
  "cowl":          (1800, 1400),  # излом капот / лобовое стекло
  "apex":          (3050, 1796),  # ВЕРШИНА — ребро
}
```

Адресация по индексам ломается при первом же добавлении точки, причём молча:
геометрия построится, просто не та.

## Проверка должна считаться независимо

Ожидаемый объём считается **по формуле из тех же данных**, а не берётся из
SolidWorks:

```python
exp_vol = ((x2-x1)*(y2-y1)*(z1-z0)
           - sum((c[2]-c[0])*(c[3]-c[1])*(c[5]-c[4]) for c in cuts))
sw.check_part(doc, name, expect_volume_mm3=exp_vol, expect_box_mm=box)
```

Смысл проверки — именно в независимости пути. Сверять объём из SolidWorks с
объёмом из SolidWorks бессмысленно.

## Что это даёт

* пересборка всего проекта одной командой;
* изменение параметра не требует правки кода;
* расчёт, модель и документация не расходятся между собой;
* проверки пишутся сами собой — ожидание уже есть в данных.

## Чего это не даёт

Данными хорошо описываются призматические тела: стены, балки, плиты,
коробчатые сечения. Сложная поверхность (кузов, обтекатель) в таблицу не
ложится — там данными задаётся профиль и ключевые точки, а построение
остаётся кодом: файл данных держит опорные точки профиля, а скрипт —
логику их соединения.
