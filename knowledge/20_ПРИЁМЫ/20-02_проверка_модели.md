# Как проверять модель

## Главный принцип

**Деталь, которая открылась, — ещё не правильная деталь.**

Незамкнутый контур, молча слившиеся контуры, вырез не в ту сторону, глубина
в метрах вместо миллиметров — всё это даёт файл, который открывается и
выглядит как модель.

## Два уровня, нужны оба

| Уровень | Что ловит | Чего не ловит |
|---|---|---|
| Числовой | объём, масса, плотность, габарит, число тел | «не похоже на то, что задумано» |
| Глазами | форму, узнаваемость, грубые ошибки компоновки | отклонения в доли процента |

Полагаться на один — типичная ошибка.

**Показательный случай.** Первая версия фасонного корпуса прошла ВСЕ числовые
проверки, будучи сплошным клиновидным бруском: габарит совпадал с заданным
точно. На то, что задумано, это не походило совсем. Узнаваемость дают вырезы,
сужение в плане, наклон стенок и проёмы — ни одно из этих свойств габаритом
не измеряется.

Обратный случай тоже бывает: модель выглядит правильно, а вырез ушёл на
0.5 мм в сторону — глазами не видно, числом ловится сразу.

## Числовая проверка детали

```python
exp_vol = 2000 * 1000 * 200 - 400 * 400 * 200     # посчитано независимо
ok = sw.check_part(doc, "Тестовая плита",
                   expect_volume_mm3=exp_vol,
                   expect_box_mm=[2000, 200, 1000],
                   expect_density=2500,
                   expect_bodies=1)
```

Печатает таблицу и возвращает True/False:

```
Тестовая плита
  OK   тел в детали      получено 1            ожидалось 1
  OK   объём, мм3        получено 3.68e+08     ожидалось 368000000   откл. 0.000 %
  OK   габарит, мм       получено [2000,200,1000]  ожидалось [2000,200,1000]
  итог: все проверки пройдены
```

**Число тел — недооценённая проверка.** Два тела вместо одного означают, что
контуры не слились или вытяжка не объединилась с телом. Габарит и объём при
этом могут совпасть.

## Числовая проверка сборки

```python
ok = sw.check_assembly(asm, expect_components=3, require_fully_defined=True)
```

Главное здесь — `require_fully_defined`. Недоопределённые компоненты уедут
при следующем перестроении: модель, правильная сегодня, развалится завтра,
и причину будет не найти.

## Пропуск — это не успех

Если проверку выполнить не удалось, она помечается `ПРОПУСК` и **не
засчитывается**:

```
  ПРОПУСК пересечения компонентов   не проверено   детектор недоступен
  итог: все проверки пройдены (пропущено: 1)
```

Возвращать «проверено» для невыполненной проверки нельзя ни при каких
обстоятельствах: это хуже, чем не проверять вовсе, потому что создаёт ложную
уверенность.

## Проверка глазами

```python
sw.shaded(doc)
sw.shot_set(doc, OUT, "этап_03")
```

И **посмотреть на файлы**. Не «сохранить и идти дальше» — открыть и
посмотреть. Для модели с вертикалью Z задавать ориентацию явно, иначе
штатная изометрия покажет объект на боку (см.
[10-06](../10_API/10-06_виды_и_экспорт.md)).

Снимать виды после каждого этапа, а не в конце: так видно, на каком шаге
геометрия ушла.

## Порядок в скрипте построения

```python
doc = sw.new_part(app)
#   ... построение ...
ok = sw.check_part(doc, name, expect_volume_mm3=..., expect_box_mm=...)
path = sw.save_as(doc, ...)
sw.shot(doc, ...)
sw.close(app, doc)
if not ok:
    failed.append(name)
```

Проверять **до сохранения**, но сохранять в любом случае: файл с ошибкой
нужен, чтобы посмотреть, что получилось. Список неудач печатается в конце —
прогон не останавливается на первой ошибке, иначе за один запуск находится
ровно одна проблема.

## Честный отчёт

В конце прогона — сводка без приукрашивания:

```
Построено 8 из 9
  не удалось: 09_Rama_3D: вырез не создан (контур не замкнут)
```

Если часть не получилась, так и написать. Скрипт, который печатает «готово»
при трёх непостроенных деталях, обесценивает все остальные свои сообщения.
