# Система координат

## Записать до начала работы

Система координат выбирается один раз, записывается в README проекта и
дальше не меняется. Переделка на середине стоит дороже, чем кажется:
координаты уже разошлись по данным, расчётам и снимкам.

Примеры из проектов:

**Строительная модель** — план в плоскости «Сверху»:
```
глобальный X = X плана
глобальный Y = высота
глобальный Z = −Y плана
```

**Модель автомобиля, начало на земле под передним бампером:**
```
Z — вдоль машины, нос в Z = 0, корма в Z = −5683
Y — высота от земли
X — поперёк, борта в X = ±1000
```

**Автомобиль с расчётами** — своя автомобильная система:
```
X назад от переднего бампера, Y влево, Z вверх от опорной плоскости
```

Три задачи — три разные системы. Это нормально: каждая удобна для своей
области. Ненормально — не записать выбранную.

## Соответствие осей эскиза и модели

Плоскость эскиза определяет, какими осями модели становятся оси эскиза.
Проверено на плите 2000 × 1000, вытянутой на 200 мм:

| Плоскость эскиза | X эскиза | Y эскиза | Направление вытяжки |
|---|---|---|---|
| Сверху (индекс 1) | X модели | −Z модели | Y модели (вверх) |
| Спереди (индекс 0) | X модели | Y модели | Z модели |
| Справа (индекс 2) | Z модели | Y модели | X модели |

Проверка: эскиз `rect(0, 0, 2000, 1000)` на плоскости «Сверху», вытяжка 200
дала габарит `[2000, 200, 1000]` — то есть X = 2000, Y = 200 (высота),
Z = 1000. Именно поэтому в строительной модели выше глобальный Z равен
минус Y плана.

**Не полагайтесь на память — проверьте на одной пробной детали** в начале
проекта и запишите результат. Это пять минут, которые экономят час.

## Моделировать сразу в координатах сборки

Если детали строятся скриптом, каждую деталь моделируйте **на её месте в
общей системе координат**, а не в нуле.

```python
# стена от 160 до 9730 по X, на отметке от 0 до 2700 по высоте
with sw.Sketch(doc, sw.TOP) as sk:
    sk.rect(160, 9075, 7670, 9340)
sw.extrude(doc, sk.feature, 2700, start_offset=0)
```

Тогда сборка получается совпадением одноимённых базовых плоскостей
(способ 3 в [10-04](../10_API/10-04_сборки.md)), компоненты полностью
определены, и ни одна координата не дублируется между деталью и сборкой.

Плата — деталь неудобно смотреть отдельно: она висит далеко от своего
начала координат. Это дешевле, чем расстановка по координатам в сборке.

## Смещение по высоте

Деталь, лежащая не на нулевой отметке, строится через `start_offset`:

```python
sw.extrude(doc, sk.feature, depth=z1 - z0, start_offset=z0)      # z0 >= 0
sw.extrude(doc, sk.feature, depth=z1 - z0, start_offset=abs(z1),
           reverse=True)                                          # ниже нуля
```

При `start_offset != 0` начальное условие должно быть `START_OFFSET` (3) —
`swkit.extrude` подставляет его сам. При прямом вызове API забытая тройка
означает, что смещение игнорируется молча, и деталь встанет на нулевую
отметку.

## Проверка координат габаритом

Габарит проверяет не только размеры, но и **положение**:

```python
lo, hi = sw.bbox_union_mm(doc)
assert abs(lo[1] - z0) < 0.001, "деталь не на своей отметке"
```

Ожидаемый габарит полезно выписывать целиком, вместе с положением:

```python
exp_box = [x1*MM, z0*MM, -y2*MM, x2*MM, z1*MM, -y1*MM]
```

Это ловит ошибку соответствия осей сразу, на первой детали.
