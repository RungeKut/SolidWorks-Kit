# Проверить пересечения штатным способом не получается

## Что происходит

Штатный путь из документации:

```python
mgr = doc.Extension.CreateInterferenceDetectionManager()
mgr.GetInterferences()
```

На этой установке недоступен ни одним способом:

```
позднее связывание, обычное обращение
  -> AttributeError: <unknown>.CreateInterferenceDetectionManager
позднее связывание, _FlagAsMethod
  -> com_error (-2147352570, 'Неизвестное имя.')
раннее связывание, cast к IModelDocExtension
  -> AttributeError: объект не имеет атрибута CreateInterferenceDetectionManager
```

Анализ сгенерированной типовой библиотеки SolidWorks 2025 показывает:
интерфейс `IInterferenceDetectionMgr` **в библиотеке есть** (с методами
`GetInterferences`, `GetInterferenceCount`, `GetInterferenceComponents`), но
**фабрики, которая его создаёт, нет ни на одном интерфейсе**.

Запасной путь `IAssemblyDoc::ToolsCheckInterference2` вызывается без ошибки,
но возвращает `(None, None)` — в том числе на сборке, где детали заведомо
пересекаются (два куба 500×500×500 с перекрытием 250 мм).

## Почему

Причина не установлена. Вероятные версии: метод требует иного способа
получения, чем описано, либо не выставлен через COM в этой сборке продукта.
**Версия не проверена** — если понадобится, начинать с поиска по
`swapi-pilot` и с `discover_solidworks_docs`.

## Как правильно (обходной путь)

Пересечения ловятся косвенно — по объёму. Пересекающиеся тела в сборке
считаются один раз, поэтому объём сборки окажется **меньше** суммы объёмов
компонентов:

```python
v_asm, v_sum, ok = sw.check_volume_additive(app, asm, part_paths)
if not ok:
    print("объём сборки %.0f < суммы %.0f -> компоненты пересекаются"
          % (v_asm, v_sum))
```

Кратность важна: если деталь вставлена четырежды (колёса), её путь
передаётся четыре раза.

Способ грубее штатного — он не назовёт, какие именно компоненты пересеклись,
и не заметит пересечение нулевого объёма (касание). Но он ловит главное:
грубую ошибку расстановки.

## Чего делать НЕЛЬЗЯ

Возвращать пустой список при недоступном детекторе. Пустой список означает
«пересечений нет», и сборка с грубой ошибкой прошла бы проверку молча.
`swkit.assembly.check_interference` возвращает в этом случае `None`, а
`check_assembly` печатает `ПРОПУСК` и не засчитывает проверку:

```
  ПРОПУСК пересечения компонентов   не проверено   детектор недоступен
  итог: все проверки пройдены (пропущено: 1)
```

Модель не считается проверенной по признаку, который не проверяли.

## Чем подтверждено

Проверены: сборка без пересечений и сборка с заведомым пересечением
(два куба с перекрытием 250×250×500 мм). Оба раза
`ToolsCheckInterference2(0, None, False)` вернул `(None, None)` — то есть
не отличил одну от другой.

## Что делать при обновлении SolidWorks

Перепроверить первым делом: это единственная непройденная проверка в наборе.
Если заработает — заменить обходной путь на штатный и понизить статус этой
записи до `устарело`, сохранив историю.
