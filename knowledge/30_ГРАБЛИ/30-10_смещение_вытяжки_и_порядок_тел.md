# Смещение вытяжки, порядок тел и затенение с кромками

Три граблей, найденных на одной задаче: построить сотню призматических
брусков в общей системе координат, каждый одним эскизом и одной вытяжкой.

## 1. `start_offset` при `reverse=True` откладывается ВСЁ РАВНО в плюс

Начальное смещение задаётся расстоянием и **не наследует знак от
`reverse`**. Вытяжка с `reverse=True` и `start_offset=605` ставит тело не
на отметку −635…−605, как ожидается, а на **+575…+605**: смещение отложено
в плюс, а материал нарастает от него в минус.

Чтобы перенести начальную плоскость на другую сторону эскиза, нужен флаг
`flipStartOffset` (23-й аргумент `FeatureExtrusion3`, в `swkit.extrude` —
`flip_start`):

```python
# тело от -635 до -605 по оси вытяжки
extrude(doc, sk.feature, depth=30, start_offset=605,
        reverse=True, flip_start=True)
```

Три случая по положению ближней грани `off` относительно плоскости эскиза:

| условие | как строить |
|---|---|
| `off >= 0` | `start_offset=off` |
| `off + b <= 0` | `start_offset=abs(off + b)`, `reverse=True`, `flip_start=True` |
| `off < 0 < off + b` | `both=True`, `depth=off + b`, `depth2=-off` |

**Почему это дорого.** Ошибка проявляется только при отрицательном
смещении. Если пробная деталь построена с положительным, проверка
проходит, а в изделии зеркально встаёт ровно половина тел — та, что лежит
по другую сторону плоскости симметрии. Габаритный ящик всей детали при
этом **сходится**: размах по оси тот же самый. Числовая проверка габарита
такую ошибку не ловит в принципе, её видно только на виде сверху.

Отсюда правило: в калибровочную деталь обязательно включать знаковые
случаи — отрицательное смещение и переход через ноль.

## 2. `GetBodies` возвращает тела НЕ в порядке построения

Сопоставлять i-е тело с i-й операцией нельзя: порядок другой. Попарная
сверка тел с исходными данными по индексу даёт полную бессмыслицу —
«ждали (540, 620, 290), получили (1410, 0, −850)» на совершенно исправной
модели.

Надёжные способы:

* считать **число** тел и суммарный объём (порядок не важен);
* брать габарит всей детали `bbox_union_mm` после каждого шага;
* если нужно именно тело, искать его по положению, а не по индексу.

Суммарный объём — сильная проверка сам по себе: если тела нигде не
пересекаются по построению, объём модели обязан совпасть с арифметической
суммой объёмов заготовок до последнего кубического миллиметра. Расхождение
означает наложение тел.

## 3. Затенения с кромками через API нет

Ни одного из имён не существует при позднем связывании:

```
ViewDisplayShaderewithedges   ViewDisplayShadedwithedges   ViewDisplayShadedWithEdges
```

Работает только `ViewDisplayShaded`. `swkit.views.shaded(with_edges=True)`
теперь перебирает варианты и молча отступает к обычному затенению: раньше
безусловный вызов несуществующего имени ронял скрипт **после** того, как
геометрия уже построена, и прогон терялся целиком.
