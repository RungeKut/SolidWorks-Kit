# Третий аргумент SaveAs3 — это не «тихий режим», а набор флагов

## Что происходит

Распространённая запись:

```python
doc.SaveAs3(path, 0, 2)
```

Файл появляется на диске, вызов не падает. Но открытый документ **сохраняет
старое имя**:

```
после SaveAs3: title = Сборка18 | path = ''
```

Дальше всё разваливается не там, где ошибка. Сборка строится так: создать
документ сборки, сохранить его, открыть детали, сделать сборку активной,
вставлять компоненты. Активация идёт по имени файла:

```python
sw.ActivateDoc3("Тест_сборка.SLDASM", False, 0, errors)
```

Документа с таким именем нет — он всё ещё «Сборка18». Активной остаётся
последняя открытая ДЕТАЛЬ. Следующий вызов `AddComponent5` уходит в деталь,
и появляется совершенно неинформативное:

```
AttributeError: <unknown>.AddComponent5
```

Искать причину начинают в COM-связывании, а она — в аргументе сохранения
двумя шагами выше.

## Почему

Третий аргумент — перечисление `swSaveAsOptions_e`, набор битовых флагов:

| Значение | Имя | Смысл |
|---|---|---|
| 0 | `swSaveAsOptions_None` | обычное сохранение, документ переименовывается |
| 1 | `swSaveAsOptions_Silent` | без диалогов, документ переименовывается |
| 2 | `swSaveAsOptions_Copy` | **записать копию**, документ НЕ переименовывается |
| 4 | `swSaveAsOptions_SaveReferenced` | сохранить и связанные документы |

Флаг 2 — это команда «Сохранить как копию», пункт меню с галочкой «Сохранить
как копию и продолжить». Он существует именно для того, чтобы НЕ менять
текущий документ.

## Как правильно

Для моделей — настоящее «Сохранить как» (флаг 1):

```python
sw.save_as(doc, path)                    # внутри флаг 1 (Silent)
```

Для экспорта и снимков — копия (флаг 2), чтобы открытая модель не
превратилась в `Деталь.STEP`:

```python
sw.export(doc, r"...\Деталь.STEP")       # внутри флаг 2 (Copy)
sw.shot(doc, r"...\вид.png", view="iso") # внутри флаг 2 (Copy)
sw.save_as(doc, path, as_copy=True)      # явная копия, если нужна
```

## Как неправильно

```python
doc.SaveAs3(path, 0, 2)        # для модели — документ не переименуется
```

Ошибка коварна тем, что на деталях не проявляется: они сохраняются и сразу
закрываются, имя документа роли не играет. Тот же код, применённый к
сборке, ломает всю цепочку.

## Отдельно: возвращаемое значение не означает успех

```
options=0 -> вернул 0 | файл True | title Опция0.SLDASM
options=1 -> вернул 0 | файл True | title Опция1.SLDASM
options=2 -> вернул 0 | файл True | title Сборка21
```

`SaveAs3` вернул `0` во всех трёх случаях, включая успешные. Проверять надо
**существование файла на диске**, а не результат вызова. `swkit.save_as`
так и делает.

## Чем подтверждено

Таблица выше — прямой перебор на документе сборки. Флаги 0 и 1
переименовывают документ (`GetTitle` и `GetPathName` меняются), флаг 2 — нет.
